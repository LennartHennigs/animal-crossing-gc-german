# Animal Crossing German localization — working folder

Goal: rebuild the USA `GAFE01` ISO with German text extracted from the EU disc,
for use with the OpenCrossing-Anbernic port. Status: v4 ISO verified booting
with German text on the Anbernic (2026-07-19). This file is the current-state
authority; earlier debugging narrative (superseded v1 model, RARC base bug)
lived in FINDINGS.md/PLAN.md, since deleted as redundant with the gotchas below.

## Folder layout

| Folder | Contents |
|---|---|
| `isos/` | Source ISOs: `Animal Crossing (USA).iso`, `Animal Crossing (Europe) (En,Fr,De,Es,It).nkit.iso` |
| `extracted/` | Everything pulled from the discs: TGCs, PAL/US arcs, `us_message_data*` , `de_/en_msg.bin` |

| _(reference)_ | Not vendored in-repo (removed before public release — third-party code). Consult upstream directly: ac-decomp (`m_msg.h`, `m_font.h`, `m_string.c`, `*.c_inc`, `jsyswrap.cpp`) at github.com/ACreTeam/ac-decomp, and Cuyler36's Animal-Crossing-Text-Editor for the charmap tables |

Port source: https://github.com/GabeConway/OpenCrossing-Anbernic — port harness
in `pc/` (`pc_pad.c` button mapping, `jsyswrap.cpp` heap/ARAM setup); game
logic from ACreTeam/ac-decomp.

On device: no save states — save in-game only (Gyroid next to the player
house). Select = port settings overlay, Select+Start = quit.

## Reproduce

```bash
./build.sh   # p8 -> p10 -> p11 -> p13, prints the final ISO sha1
```

Verified reproducible: full re-run yields a bit-identical ISO
(sha1 `fed8736178fe9e66d3e206a10fd6e7cb530e72dd`, v11 build: v10 + US-empty
bank slots stay empty — difflib gap-fill had planted German strings in them;
the engine treats size 0 as "clear to spaces" and name-entry prefill reads
these, so a filled slot leaked into the typed town name, "bonnSchmetterling").

p9/p12 (append-style packing, deleted) are superseded: the port mounts
forest_1st/2nd.arc into a fixed ARAM pool (all files attr 0x21, see
ac-decomp `jsyswrap.cpp` JW_Init), and the append strategy's ~3 MB of dead bytes
overflowed it → boot segfault on the Anbernic. `p13_compact_pack.py` rebuilds
the data areas compactly (ARAM payload +90 KB over stock).

## Tools

| Script | Purpose |
|---|---|
| `gc_fst.py` | List/extract files from a GameCube ISO (`ls`/`x` modes) |
| `rarc.py` | List/extract files from a RARC `.arc` archive |
| `msglib.py` | Shared parsing: US string tables (end-offset semantics!), PAL BMG (`ROOT`+`MESGbmg1`), control-code stripping, `CC_SIZE` table |
| `p8` → `p10` → `p11` → `p13` | Pipeline, in order: main dialog bank → per-bank extract (into `build/banks/`) → rebuild 10 secondary banks → compact v4 arcs + final ISO |

## Gotchas learned the hard way

- #1: RARC data area base is `header[0x0C]+0x20`, NOT `header[0x08]+0x20`.
  The wrong base shifts every extracted file and produced a bogus
  "entries start mid-word / pagination chains" model.
- US table entries are END offsets (`msg[i] = data[table[i-1]:table[i]]`).
- Messages are NOT null-terminated; control-code params may contain 0x00.
- US entries ↔ PAL BMG messages are ~1:1 at the same index (13k byte-identical
  after code-stripping). Main-bank entries 0/1/7 are charset/debug tables and
  16272 is US-only — these 4 legitimately stay English.
- BMG DAT1: bound messages by next-largest offset, then `rstrip(b"\0")`;
  naive zero-scan misreads tag payloads and can walk megabytes.
- PAL character encoding == US encoding (umlauts included); only the control
  code/tag systems differ.
- npc_name_str_table.bin: fixed 8-byte name records, US/DE same size.
- forest_1st/2nd.arc data areas load whole into a fixed ARAM pool (all files
  attr 0x21; header 0x18 = ARAM length). Keep them compact — appending data
  while leaving dead bytes overflowed the pool and segfaulted the port at boot.
- Flow-critical control codes (choice menu 0x0D, next-message links 0x0E-0x15,
  select strings 0x16-0x18, 0x5E/0x62/0x63/0x77-0x7A) can't be learned from PAL
  tags: select-string payloads vary per message and PAL restructures some
  dialogs into 5-byte stubs. `msglib.fix_flow` transplants them verbatim from
  the US entry (valid because the select bank is index-aligned); without it,
  choice dialogs show no Ja/Nein options and branch targets derail (v4 bug).
- PAL tags carry params (color, char/line scale, BGM id) in trailing payload
  bytes; a per-tag template replays one frozen param everywhere (tiny first
  letters via SetCharScale 0x54, wrong BGM). Conversion must be payload-aware:
  exact `(tag,payload)` lookup first, then pass-through (payload == US params,
  e.g. Bgm 0x56/0x57), then nearest-payload for scale `7,255,1` (PAL units ≈3×
  US), then the generic template.
- PAL highlights words with stateful color tags `{80 06 ff 00 00 id}` /
  `{... 00}` (off); the US engine has no reset (0x04 is PressButton!). Convert
  to count-based `7f50 RGB n` with n counted on the GERMAN span (color_span),
  emit nothing for the off tag. The v7 grey-text bug was the generic template
  (`7f05 969696`) painting every highlight grey until reset.
- SetDemoOrder codes (0x08-0x0C) drive the intro/demo cutscene scripts and
  MsgTimeEnd (0x58) auto-advances timed messages; the PAL script data doesn't
  always carry equivalents, so conversion can silently lose them → soft-lock
  (player-select name question hung after choosing). `fix_flow` appends lost
  ones before the terminator (position-correct ones stay in place).
- The player-select option "I'm new" is not in any of the 11 message banks —
  it comes from elsewhere (port binary or another asset); still English.
- `string.bin` BMG's INF1 size field is file-absolute (others are
  section-relative) — `load_bmg` tries both. PAL string-bank entries carry
  3-byte grammar prefixes (gender/number/class, e.g. `00 ff ff`): keep them
  when parsing PAL data, but STRIP them for the US engine
  (`p11.strip_grammar_prefix`) — mString copies these strings raw into
  fixed-size name fields, so prefixes render as junk and kill the padding
  (the "bonnii Ä…" town-name bug). Charmap note: low bytes are glyphs
  (0x02='Ä', 0x92='ü'), hence the constrained match.

## History (v2/v3, superseded packers)

`rarc.py` base bug (wrong data-area base offset) invalidated the v1 chain/dialog machinery.
v2: re-extract with fixed `rarc.py`, `p8_final_rebuild.py` (difflib
near-identity entry map, 199-entry tag table, `MSG_BUF_MAX` 1536 guard —
max entry 1508). v3 added the 10 secondary banks + German npc names (p10/p11).
v2/v3 packed by appending grown data to the arcs (p9/p12) — worked in
emulation-style checks but overflowed the port's ARAM pool; replaced by the
compact p13 (v4).
